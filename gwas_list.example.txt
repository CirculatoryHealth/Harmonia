# gwas_list.example.txt — example config file for gwaslab.process.submit.sh
#
# This file shows three representative entries covering different use-cases:
#   • CAD_Aragam  : binary trait with N_controls; hg19; EUR
#   • CHARGE_CAC_EA : quantitative trait; hg19; EUR
#   • AF          : multi-ancestry (PAN); hg19; requires large MEM_LIGHT (256G)
#                   because of many columns and allele-flipping at check-ref.
#
# Copy this file to gwas_list.txt (gitignored) and update COL1 paths to point
# to your local GWAS summary-statistics files.
#
# Semicolon-separated, one GWAS per line.  Use . for optional columns that do not apply.
#
# COL1  Full path to input GWAS file (directory + filename)
# COL2  GWAS name         → used for --gwas and the output subdirectory
# COL3  Population        → EUR / EAS / SAS / AFR / AMR / PAN
# COL4  Build             → 18 / 19 / 38
# COL5  N (total)         → integer or .
# COL6  N_cases           → integer or .
# COL7  N_controls        → integer or .
# COL8  MEM               → SLURM memory for HEAVY stages (process-infer-strand,
#                           process-assign-rsid, process-check-af); e.g. 128G or 256G
# COL9  TIME              → SLURM time limit for HEAVY stages (HH:MM:SS, e.g. 96:00:00)
# COL10 MEM_LIGHT         → SLURM memory for LIGHT stages (process-normalize,
#                           process-check-ref, merge); e.g. 32G or 64G or 128G
# COL11 TIME_LIGHT        → SLURM time limit for LIGHT stages (HH:MM:SS, e.g. 24:00:00)
#
# Note: if COL5, COL6, and COL7 are all provided, --force-n is added automatically.
# Note: rows starting with # are ignored by the submit scripts.
# Note: MEM_LIGHT should be set higher if a study has many columns or many alleles
#       to flip (e.g. multi-ancestry meta-analyses like AF can require 256G at check-ref).
#
